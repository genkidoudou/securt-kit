## Context

参见 `proposal.md` 的动机。当前 Monitor 是单页静态界面，主导航通过按钮的 `data-tab` 与 `<name>Tab` 内容节点切换，所有页面结构、样式和行为分别集中在 `index.html`、`style.css` 和 `app.js`。项目已有通用剪贴板方法与错误通知，但成功通知默认静默；现有功能页标题结构也不完全一致。

本变更必须保持工作台默认激活、现有控件 ID 和所有后端接口不变。帮助及项目文档需要随静态资源离线工作，并避免重新造成页面纵向无限增长。

## Goals / Non-Goals

**Goals:**

- 用一致的标题栏和帮助按钮覆盖六个现有主功能页。
- 以单个可访问弹窗承载六套上下文帮助，避免重复弹窗结构。
- 将项目基础文档作为新的主 Tab 静态内嵌，并提供章节导航和代码复制。
- 复用现有原生 JavaScript 架构，不增加构建流程或第三方前端依赖。
- 让结构、关键内容和交互可通过资源测试及浏览器冒烟验证。

**Non-Goals:**

- 不把仓库全部 Markdown 文档动态转换或同步到 Monitor。
- 不提供全文搜索、在线编辑、文档版本切换或远程文档加载。
- 不改造现有主导航框架，不拆分当前静态资源文件。
- 不修改任何 Monitor 后端 API。

## Decisions

### 1. 帮助入口使用统一标题栏和内联 SVG 眼睛图标

每个主功能页增加一致的 `section-head` 标题区，右侧按钮使用 `data-help-topic` 标识帮助主题。按钮包含眼睛 SVG、可见的「使用说明」文本和 `aria-label`。

选择内联 SVG 而不是 Emoji 或图标库：不同平台 Emoji 外观不可控，引入图标库又会破坏离线和零依赖约束。可见文本避免用户只能猜测图标含义。

工作台当前没有页面标题，将增加紧凑标题栏；其他页面只包裹或调整现有标题，不改变表单控件 ID。

### 2. 使用一个静态模态窗口和多个 HTML template

`index.html` 放置一个具有 `role="dialog"`、`aria-modal="true"` 的隐藏帮助弹窗，以及六个 `<template>` 帮助内容。打开时，`app.js` 根据 `data-help-topic` 克隆对应模板到弹窗正文。

选择 HTML template 而不是在 JavaScript 中拼接大段 HTML：文档结构留在页面标记中更易维护，克隆静态模板不会引入未转义输入。也不为每个页面复制完整弹窗，以避免重复关闭和焦点逻辑。

统一帮助控制器记录触发按钮，打开后聚焦关闭按钮；关闭按钮、遮罩点击和 Escape 均调用同一关闭方法，随后把焦点还给触发按钮。正文限制最大高度并内部滚动。

### 3. 项目文档作为静态主 Tab

主导航新增 `data-tab="docs"`，内容节点使用 `docsTab`，从而直接复用现有 Tab 切换规则。工作台仍保持默认激活。

文档区使用 `docs-layout`：桌面端左侧为章节目录，右侧为正文；900px 以下改为顶部横向滚动目录。正文由语义化 section 和原生锚点组成，不要求额外路由或状态管理。

文档内容以已确认设计中的主题为边界，并从 `README.md`、`docs/QUICK-START.md` 及专项文档提炼。它是可独立使用的快速指南，不逐字复制仓库文档。

### 4. 代码复制使用声明式目标和专用反馈

每个复制按钮通过 `data-copy-target` 指向同一示例容器中的 `<code>`。事件委托读取 `textContent`，调用已有 `utils.copyToClipboard`。

成功时临时把按钮文字改为「已复制」，同时更新 `aria-live` 状态节点；失败时使用现有错误通知并保留可手动选择的代码文本。不能直接依赖 `utils.showNotification` 的成功分支，因为该分支当前静默，无法满足可感知反馈要求。

### 5. 文档样式与功能样式隔离

新增样式均使用 `help-`、`docs-` 和 `section-head` 前缀。模态正文和文档正文设置视口相关最大高度与 `overflow: auto`；代码块允许自身横向滚动，但页面根级不产生横向溢出。

窄屏下模态窗口缩小边距，文档双栏变单栏，章节目录改为横向导航。现有 SQL、结果表和表单响应式规则不改。

### 6. 测试采用资源契约与浏览器行为两层验证

JUnit 资源测试验证：

- 六个帮助主题入口和模板存在。
- 共用弹窗的无障碍属性、关闭入口和项目文档 Tab 存在。
- 项目文档包含规定主题与复制目标。
- CSS 包含内部滚动和 900px 响应式规则。
- JavaScript 包含打开、三种关闭路径、焦点恢复及复制反馈逻辑。

浏览器冒烟验证主 Tab、六个帮助入口、弹窗关闭方式、复制反馈和窄屏无溢出。现有 `mvn -pl securt-kit-monitor -am test` 作为模块回归。

## Risks / Trade-offs

- [静态项目文档可能与仓库文档逐渐不一致] → 只维护稳定的接入要点，并在测试中断言关键配置项；后续配置契约变更时同步更新。
- [集中式 `index.html` 进一步增长] → 帮助内容使用独立 template 分区并保持统一结构；本次不引入新的资源加载机制，以避免扩大部署兼容面。
- [模态窗口键盘行为不完整导致可访问性下降] → 明确测试打开聚焦、Escape 关闭和焦点恢复；所有操作保留可见按钮。
- [代码复制受浏览器权限限制] → 复用已有降级复制，失败时保留可选择文本并显示错误反馈。
- [新增顶部 Tab 在窄屏拥挤] → 继续使用主导航横向滚动能力，并验证 900px 以下无页面级溢出。

## Migration Plan

1. 先增加资源契约测试并确认其针对当前页面失败。
2. 添加帮助模板、共用弹窗、项目文档 Tab 和相应样式、行为。
3. 运行 Monitor 与依赖模块测试，并在测试应用执行桌面及窄屏冒烟。
4. 部署时随现有 Monitor 静态资源一并发布，无数据库或配置迁移。
5. 如需回滚，仅恢复三项静态资源及对应测试；后端无需回滚。
