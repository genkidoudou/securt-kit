# SQL 页面分区优化设计

## 状态

待实施。

## 目标

优化 Monitor 的 SQL 页面，将查询和修改操作明确分区，并避免输入、输出和结果表持续撑高页面导致频繁纵向滚动。

对应静态原型：

`docs/superpowers/mockups/sql-page-redesign/index.html`

## 页面结构

SQL 页面保留在现有顶部导航中，页面内部增加两级切换：

1. 一级切换为「查询」和「修改」。
2. 「修改」内部增加「SQL 解析」和「参数加密」二级切换。

现有三个功能及后端接口全部保留，只调整页面布局和前端切换逻辑。

## 查询区

- 数据源、每页大小和页码合并到紧凑工具栏。
- SQL 输入框位于工具栏下方。
- 查询和清空按钮位于输入框与结果之间。
- 查询结果使用固定高度容器，结果较多时容器内部滚动。
- 表头在结果区域滚动时保持可见。
- 已执行 SQL、统计信息和查询结果继续保留，但使用紧凑布局呈现。

## 修改区

### SQL 解析

- 左栏展示数据源、SQL 输入和操作按钮。
- 右栏展示占位符映射及需要加密的字段。
- 右栏结果区域独立滚动，不撑高整个页面。

### 参数加密

- 左栏展示数据源、原始 SQL 输入和操作按钮。
- 右栏展示加密后的 SQL、处理统计和复制按钮。
- 输出区域独立滚动。

## 状态与切换

- 查询、SQL 解析和参数加密分别保存自己的 SQL 草稿。
- 切换功能时不再自动将当前 SQL 覆盖到另一个功能。
- 已生成的结果在切换后保留，清空按钮只清理当前功能。
- 页面首次打开默认进入「查询」。
- 修改页首次打开默认进入「SQL 解析」。

## 响应式规则

- 宽度大于 900px 时，修改区使用左右两栏。
- 宽度不大于 900px 时，修改区变为上下排列。
- 小屏下结果区仍设置合理最大高度并内部滚动。
- 页面控件沿用 Monitor 当前颜色、按钮和字体风格。

## 兼容性与范围

- 不修改后端 API、请求字段和响应结构。
- 保留现有 DOM 元素 ID，避免破坏已有 JavaScript 事件绑定。
- 仅调整 SQL 页相关 HTML、CSS 和模式切换逻辑。
- 不修改其他 Monitor 功能页。

## 验收标准

1. SQL 页面一级仅显示「查询」「修改」两个入口。
2. 修改页可切换「SQL 解析」「参数加密」。
3. 桌面端修改页输入和输出左右并列。
4. 大量查询结果、解析结果或加密 SQL 不再持续增加整页高度。
5. 三种功能均可正常请求原有接口并展示结果。
6. 三种功能的 SQL 草稿互不覆盖。
7. 900px 以下布局可用，无横向溢出。
