# Monitor UI 重设计（方案 3：多 Tab 视觉翻新）

> 状态：**已实现**  
> 版本：v1.0  
> 日期：2026-09-07  
> 线框：`docs/superpowers/mockups/monitor-redesign/approach-3-tabs.html`  
> 目的：在保留 Tab 信息架构的前提下，重做 `/monitor` 视觉与交互，默认进入工作台，合并 SQL 子能力，理顺刷数步骤；后端仅在必要时微调。

---

## 1. 背景与目标

### 1.1 现状问题

- 顶部 8 个平铺 Tab，运维排查时定位成本高  
- 视觉偏旧，表单与结果区散乱  
- SQL 解析 / 参数加密 / 查询拆成三个 Tab，同属排查却割裂  
- 缺少「先看环境再进工具」的首页  

### 1.2 目标

1. **工作台默认首页**：状态摘要 + 常用快捷入口  
2. **视觉翻新**：深色顶栏 + 浅色内容区；统一结果面板  
3. **SQL 合并**：一个 SQL Tab，内含子模式切换；默认「查询双视图」  
4. **刷数步骤化**：选范围 → 预览 → 确认回写；未预览禁用确认  
5. **与 playground 分离**：monitor = 运维；playground = 业务演示  

### 1.3 非目标

- 侧栏分区运维台（方案 1）  
- 顶部三大场景向导壳（方案 2）  
- 合并 playground  
- 重做加密核心 / starter 装配  
- 配置热写回 YAML  

---

## 2. 决策摘要

| 议题 | 决策 |
|------|------|
| 方案 | **方案 3**：多 Tab 视觉翻新 + 工作台 + SQL 合并 |
| 默认首页 | 工作台 |
| 受众 | 开发与运维都有，**偏运维排查** |
| 改动深度 | 交互流可较大调整；后端按需适配 |
| 后端策略 | 优先复用现有 API；可选新增轻量 `overview` |
| 视觉参考 | `approach-3-tabs.html`（暖橙主操作 + 青绿次要） |

---

## 3. 信息架构

| Tab | 说明 |
|-----|------|
| **工作台**（默认） | 摘要卡片 + 快捷入口（SQL 对照 / 刷数 / 配置） |
| 加密解密 | 单值 encrypt / decrypt / sign / verify |
| 单行验签 | 表 + id + 可选主键列 |
| 刷数作业 | 步骤条：范围 → 预览 → 确认回写 |
| **SQL** | 子模式：查询双视图（默认）/ 解析 / 参数加密 |
| 数据初始化 | 保留，靠后 |
| 配置信息 | 配置全览（mode、表字段、digest、开关） |

路径仍为可配置的 `/monitor`（默认）。

---

## 4. 视觉与交互

### 4.1 视觉

- 深色顶栏（标题 + Tab + 退出）；浅色内容底  
- 主操作色：暖橙；次要/成功：青绿  
- 字体：标题 Space Grotesk（或等价）；正文 Manrope；结果区 JetBrains Mono（可通过 CDN 或系统等宽回退）  
- 工作台用入口卡；工具页为清晰表单，避免按钮墙  

### 4.2 交互约定

1. 打开 `/monitor/`（或根路径重定向后）默认展示**工作台**  
2. 工作台快捷入口切换到对应 Tab（不新开路由）  
3. SQL Tab 内三个子模式互斥切换；切换不丢已填 SQL（同会话内保留）  
4. 刷数：步骤指示；`apply` 仅在成功 `preview` 且用户确认后可点  
5. 结果统一深色等宽面板；成功/失败色标  
6. 多数据源时顶栏或共用选择器可见；单 DS 隐藏  
7. 窄屏：Tab 横向滚动；双列表单单列  

### 4.3 登录

保留现有登录门禁与会话逻辑；登录成功后进入工作台（而非「加密解密」）。

## 5. 落地范围

### 5.1 前端（主改动）

模块：`securt-kit-monitor/src/main/resources/support/http/resources/`

| 文件 | 变更 |
|------|------|
| `index.html` | 工作台、Tab/SQL 子切换、刷数步骤结构 |
| `css/style.css` | 按方案 3 重做样式 |
| `js/app.js` | 默认 Tab、导航、子模式、结果渲染；复用现有 API 调用 |

### 5.2 后端（按需）

- **默认**：不改接口契约；继续使用  
  `config.json`、`datasources.json`、`encrypt/decrypt.json`、`digest.json`、`row/verify.json`、`batch/preview|apply.json`、`parse-sql|encrypt-sql|query-sql.json`、`data-init/*`  
- **可选**：`GET /api/overview.json` — 工作台一次取：mode、表/摘要计数、关键开关、数据源列表；若实现成本高于前端组合现有接口，则**不做**，由前端组合 `config` + `datasources`

## 6. 验收标准

1. `/monitor/` 登录后（或免登录时）默认落在**工作台**  
2. 工作台三项快捷入口能跳到 SQL / 刷数 / 配置  
3. SQL 原三能力均可在同一 Tab 内完成  
4. 刷数：未预览时确认禁用；预览成功后可确认回写  
5. 配置、单值加解密、单行验签、数据初始化功能不回归  
6. 现有 monitor 单测（如 `MonitorOpsUnitTest`）通过；静态资源路径仍为 `/monitor/css|js/...`  

---

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| `app.js` 体量大，重写易漏绑定 | 按 Tab 分区改造；每区改完手动点验 |
| CDN 字体在内网不可用 | CSS 提供系统等宽/无衬线回退 |
| overview 接口争论 | 默认前端组合，不做新接口除非明确需要 |

---

4. 刷数步骤条与按钮态  
5. 文档与冒烟验收
